# Pipeline Trace — Reference Implementations & Recommended Architecture

**Purpose.** Trace the actual implementation of the topology-optimization pipeline in each reference
repository, identify the exact files/functions per stage, compare the approaches, and recommend a single
architecture for our own Python solver. **No production code is written or copied** — this document is
analysis only.

**Repositories** (see `reference_code/REFERENCE_MANIFEST.md` for provenance/licenses):

| Short | Repo | Language | Paradigm |
|---|---|---|---|
| TF | topflow | MATLAB | Density-based, **discrete adjoint**, NS, OC update |
| STO | Stokes_TO | C++/CUDA | Density-based, **discrete adjoint**, Stokes, **MMA** update |
| CA | cashocs | Python/FEniCS | **Level-set** topology, topological derivative, Stokes |
| TY | topy | Python | Density-based (structural), OC update, Sigmund filter |
| DA | dolfin-adjoint | Python/FEniCS | Automated tape-based discrete adjoint |
| SOF | shapeOptimizationFoam | C++/OpenFOAM | **Continuous adjoint**, shape (not topology) |

The traced pipeline is: **design variable → material/porosity interpolation → forward flow solve →
objective → adjoint solve → gradient → filtering → optimization update → geometry extraction.**

---

## 1. topflow (MATLAB) — primary blueprint

`topFlow.m` is the single driver (~200 lines). All numeric kernels are **generated by the Symbolic Math
Toolbox** from `analyticalElement.m` (181 lines of symbolic weak-form derivation) — the generated files
are enormous (e.g. `JAC.m` = 14,757 lines). This is a key architectural fact: TF's per-element matrices
are *code-generated*, not hand-written.

| Stage | Implementation (exact location) |
|---|---|
| Design variable | `xPhys` — `nely×nelx` cell densities; init `xinit = volfrac` (`topFlow.m`, "INITIALISATION") |
| Interpolation | Inline in `topFlow.m` "MATERIAL INTERPOLATION": `alpha = alphamin + (alphamax-alphamin)*(1-xPhys)./(1+qa*xPhys)` (Borrvall–Petersson) with `alphamax = 2.5*mu/(0.01^2)`, plus derivative `dalpha`; continuation `qavec = qinit./[1 2 10 20]`, `conit = 50` it/step |
| Forward solve | Newton loop (`topFlow.m` "NON-LINEAR NEWTON SOLVER"): residual `RES.m` + Jacobian `JAC.m` (both generated), sparse global assembly via index vectors `iR/jR/iJ/jJ`, BC projection `J = (ND'*J*ND+EN)`; parabolic optimal-damping line search on residual norms; retry-from-zero on failure. Stabilized Q1-Q0 FEM: SUPG/PSPG τ (conv `h/(2|u|)`, `rho*h^2/(12*mu)`, `rho/alpha`) from `analyticalElement.m` |
| Objective | Dissipation: `phi = 1/2*alpha*u·u + 1/2*mu*dudx:(dudx+dudxᵀ)` (`analyticalElement.m` "Compute objective functional"); per-element eval `PHI.m`, summed: `obj = sum(PHI(...))` |
| Adjoint | `L = J'\RHS` with `RHS = dPHIds(...)` = ∂φ/∂state (`topFlow.m` "ADJOINT SOLVER"; `dPHIds.m` generated). **Transposed converged Jacobian** |
| Gradient | `sens = dphidg − L'*dRdg` (`dPHIdg.m` = ∂φ/∂α·dα, `dRESdg.m` = ∂R/∂α·dα; both generated) |
| Filtering | **None.** No density filter — regularization comes from the Brinkman penalization + continuation on q |
| Update | OC: `ocfac = xPhys.*max(1e-10, −sens./dV).^(1/3)`; bisection on Lagrange multiplier for `volfrac = 1/3`; move limit `mvlim = 0.2`; continuation step-up every `conit` or 5 converged iterations |
| Geometry extraction | `export.m`: MATLAB `contour(xPhys,[0.5 0.5])` → polyline cleanup → **DXF `LINE` entities** (`output.dxf`) |
| Visualization | `postproc.m`: design field, `log10(alpha)`, velocity magnitude, pressure + streamlines, centerline velocity profile |

**Takeaway.** TF is the complete reference for our architecture: same discrete-adjoint math, same
Borrvall–Petersson interpolation, OC update, 0.5-contour→DXF export. Its symbolic-codegen approach is a
convenience for FEM that we should **not** replicate — our MAC-grid FV has a simple analytic Jacobian.

## 2. Stokes_TO (C++/CUDA)

`FluidTopoOpt` (extends `OptimizerMMA`) drives everything; the flow solves run on a **MAC grid** on the GPU
via the bundled "simplex" library.

| Stage | Implementation |
|---|---|
| Design variable | Cell field `design` (0–1) ↔ MMA vector `var` (`Fluid2MMA`/`MMA2Fluid`, `FluidTopoOpt.cpp`) |
| Interpolation | `alpha(rho) = alpha_os + (alpha_us−alpha_os)*rho*(1+q)/(rho+q)` + `D_alpha` (`FluidTopoOpt.cpp:108–122`); sharpened in `Update_Fluid()` via `0.5*alpha(pow(design,3))` (SIMP-like cubic) |
| Forward solve | `Update_Fluid()`: face-penalty assembly → `steady.update_penalty(...)` → `steady.solve()` (GPU Stokes, MAC grid) |
| Objective | `energy.compute_energy(vel, p)` (`FluidEnergy.cpp`) — energy dissipation |
| Adjoint | `Update_Grad()`: `energy.compute_gradient_x/q` (adjoint RHS from state) → `steady.update_b(...)` → `steady.solve()` (same matrix) → gradient `temp_grad = −vel·steady.vel + energy.face_penalty_grad` (the u·λ dot product), chain rule `½·D_alpha(ρ³)·3ρ²` per cell |
| Filtering | None found in `fluid_topo/` |
| Update | **MMA** — `OptimizerMMA` (`simplex/src/optimization/OptimizerMma.h`) wrapping Svanberg's `MMASolver.cpp`; `movlim = 0.2`, volume constraint via `Compute_Constraint(_Grad)` |
| Validation | `Numerical_Derivative()` — prints analytic vs central-difference gradient per cell |
| Geometry | `Write_Substep` / driver `Write_Output_Files` → VTK-style field dumps |

**Takeaway.** STO confirms (a) MAC-grid Stokes + discrete adjoint with the u·λ topological derivative,
(b) MMA as the multi-constraint update, (c) that an FD gradient check is standard practice. Its GPU
complexity is only justified at 3D scale — not for our 2D solver.

## 3. cashocs (Python/FEniCS) — level-set variant

The pipe-bend demo (`demos/documented/topology_optimization/pipe_bend/demo_pipe_bend.py`) is the closest
analog to our pressure/flow objective.

| Stage | Implementation |
|---|---|
| Design variable | **Level-set function** `psi` (CG1, init −1) — not a density field (`demo_pipe_bend.py`) |
| Interpolation | Cellwise jump: `alpha = interpolate_levelset_function_to_cells(psi, alpha_in, alpha_out)` with `alpha_in = 2.5*mu/1e2**2`, `alpha_out = 2.5*mu*1e2**2` (DG0 field) — same `2.5μ/h²` heuristic as TF |
| Forward solve | Stokes weak form `F = mu*inner(grad(u),grad(v)) − p*div(v) − q*div(u) + alpha*dot(u,v)` (Taylor–Hood CG2/CG1, pointwise pressure pin); `[StateSystem] is_linear = True` → single linear solve (FEniCS) |
| Objective | `J = ∫(mu*|grad u|² + alpha*|u|²) dx + (lambda/2)*(vol − vol_des)²` — dissipation + volume penalty (`lambda = 1e4`) |
| Adjoint | Adjoint state via `cashocs/_pde_problems/adjoint_problem.py`; generalized topological derivative `dJ = (alpha_in−alpha_out)*(u·v + u·u) + lambda*(vol−vol_des)` (state + adjoint dot products) |
| Gradient | Topological derivative (adjoint-based), `[TopologyOptimization] topological_derivative_is_identical = True` |
| Filtering | None explicit — level-set projection + `requires_remeshing` provide regularization |
| Update | `TopologyOptimizationAlgorithm` / `descent_topology_algorithm.py` (descent on topological derivative), volume via `bisection.py`; config `algorithm = bfgs` for the control-type outer solver |
| Geometry | Level-set boundary → mesh + remeshing (`TopologyVariableAbstractions`) |

**Takeaway.** CA shows the *level-set alternative*: sharp interfaces and topological derivatives, but
remeshing, no density filtering, and a fundamentally different gradient. It validates our dissipation-type
pressure-drop objective (its `alpha*|u|²` term) and the `2.5μ/h²` α_max choice. Not the representation we
want for a simple structured-grid solver.

## 4. topy (Python) — pure-Python update/filter template

`topy/topy/topology.py` class `Topology` + `optimisation.py: optimise()` loop:
`fea() → sens_analysis() → filter_sens_sigmund() → update_desvars_oc()`.

| Stage | Implementation |
|---|---|
| Design variable | `desvars` (SIMP densities), loaded from TPD input files (`load_tpd_file`) |
| Interpolation | SIMP in elements/material handling; continuation on exponents `p`, `q` in `update_desvars_oc()` |
| Forward solve | `fea()` — static structural FEM (`elements.py` loads precomputed stiffness matrices from `data/*.K`) |
| Objective | Compliance-style objectives (`objfval`) |
| Adjoint | `sens_analysis()` — adjoint/chain-rule sensitivity |
| Filtering | `filter_sens_sigmund()` — **Sigmund's heuristic density-weighted filter** (cone of radius `filtrad`), applied to sensitivities (not the transposed chain-rule filter) |
| Update | `update_desvars_oc()` — OC with bisection on `lambda`, move limits, exponential damping `eta` from sensitivity ratios, p/q continuation |
| Geometry | `visualisation.py: create_2d_imag` (PNG) / `create_3d_geom` (STL) |
| Deps | numpy/matplotlib only — the "minimal dependencies" exemplar |

**Takeaway.** TY is the pure-Python template for the *non-physics* stages (OC update, filtering, output).
Its OC code (bisection on λ, move limits, continuation) is directly comparable to TF's and to our update.
Note its filter is the older *heuristic* (density-weighted) form; the mathematically consistent
chain-rule filter (as in the 88-line code and our filters.py) is preferable.

## 5. dolfin-adjoint (Python/FEniCS) — automated adjoint

`src/fenics_adjoint/`: every FEniCS solve is recorded on a tape; the adjoint is assembled automatically
as transposed linear solves.

| Stage | Implementation |
|---|---|
| Forward/adjoint | `blocks/solving.py`: `GenericSolveBlock` (with `adjoint_jacobian_solve`), `SolveLinearSystemBlock`, `SolveVarFormBlock`; `blocks/function.py`: `FunctionEvalBlock` etc.; `adjointer.py`/`tape.py` orchestrate |
| Physics | Any FEniCS PDE (Stokes/NS in canonical demos) |

**Takeaway.** DA is a correctness oracle for the *discrete-adjoint pattern* (adjoint = transpose of the
linearized forward operator). We already implement exactly this; DA is not importable into a
dependency-free solver.

## 6. shapeOptimizationFoam (OpenFOAM) — continuous adjoint, shape

`shapeOptimizationFoam.C` main loop: primal SIMPLE (`UEqn.H`,`pEqn.H` ×10) → adjoint SIMPLE
(`VEqn.H`,`qEqn.H` ×10) → objective → surface sensitivity → mesh morph.

| Stage | Implementation |
|---|---|
| Design variable | Mesh displacement (shape), not density |
| Forward solve | OpenFOAM incompressible RANS (`UEqn.H`/`pEqn.H`) |
| Adjoint | **Continuous adjoint PDE**: adjoint momentum `VEqn.H` (transpose-convection `−fvc::grad(U)&V`), adjoint pressure `qEqn.H` (Laplacian); adjoint BCs in `adjointBC.H` (`V = −(wDrag·dragDir − wLift·liftDir)` on moving patches) |
| Objective | Drag/lift via `dragAndLift.H` (weights `wDrag`, `wLift`) |
| Gradient | Surface sensitivity `surfSens = −nu*interpolate(twoSymm(grad(V)))·Sf/magSf · snGrad(U)`, mean-subtracted, → `updateMesh.H` |
| Geometry | Mesh morphing, ParaView output |

**Takeaway.** SOF is the *continuous-adjoint* school (adjoint PDE + adjoint BCs) and a shape-optimization
alternative. Its adjoint-BC treatment is useful intuition for our pressure-cap chain rule, but continuous
adjoint is more error-prone and mesh-bound than discrete adjoint on our structured grid. Relevant later as
a bridge concept toward Fluent/OpenFOAM 3D validation.

## Comparison against our priorities

| Priority | Winner | Evidence / recommendation |
|---|---|---|
| 1. Correct physics | TF + STO + CA all agree | Stokes/Brinkman with Borrvall–Petersson α, `α_max = 2.5μ/h²` heuristic shared by TF & CA; MAC-grid FV (STO) is a proven equivalent to FEM. Our MAC solver is in the right family |
| 2. Correct adjoint gradients | Discrete adjoint (TF, STO, DA) | Transposed converged Jacobian — universal; STO ships an FD checker (`Numerical_Derivative`) like our test suite. Continuous adjoint (SOF) is the less-safe alternative |
| 3. Very fast 2D | TF/STO pattern on numpy/sparse | Sparse direct solve + **LU reuse for the adjoint** (one factorization, two triangular solves); GPU (STO) unnecessary at 2D scale |
| 4. Simple Python/NumPy/SciPy | TY + our MAC grid | Hand-write the MAC-grid analytic Jacobian (banded, vectorized) — do **not** replicate TF's symbolic codegen (14k-line generated files) |
| 5. Manufacturable geometry | TF's 0.5-contour → DXF | Add tanh projection + threshold + polygon cleanup before export |
| 6. Minimal dependencies | TY, TF | numpy + scipy + matplotlib only; skip FEniCS (CA/DA), OpenFOAM (SOF), CUDA (STO) |

## Recommended single architecture (our implementation)

A standalone **Python 2D MAC-grid Stokes/Brinkman density-based topology optimizer** — i.e., the family
all flow references converge on (TF = discrete adjoint + OC; STO = MAC grid + discrete adjoint), expressed
in TY-style minimal-dependency Python. Concretely, stage by stage:

| Stage | Recommended approach | Borrowed from | Our dryer_optimizer status |
|---|---|---|---|
| Design variable | Cell-centered density ρ ∈ [0,1] over the design mask | TF, STO, TY | ✅ already this |
| Interpolation | Borrvall–Petersson rational `α_min + (α_max−α_min)·q·ρ/(q+1−ρ)`; **continuation on q** (e.g. q = 1→2→10→20, ~50 it/step); `α_max ≈ 2.5μ/h²` | TF, STO (same formula), CA (α heuristic) | ✅ formula present; add continuation on q |
| Forward solve | MAC-grid FV Stokes/Brinkman; Newton + line search; sparse direct; **reuse LU for adjoint** | STO grid, TF Newton | ✅ present |
| Objective | Tray-airflow uniformity + pressure cap (project-specific); dissipation-type pressure term `½α\|u\|² + ½μ\|∇u\|²` for pressure-drop control | CA pipe-bend dissipation form | ✅ present |
| Adjoint | Discrete adjoint: `Jᵀλ = ∂J/∂u` with the converged Jacobian | TF (`J'\RHS`), STO, DA | ✅ present |
| Gradient | Chain rule: adjoint term + ∂J/∂ρ (interpolation) + ∂(pressure cap)/∂ρ; **pass through filter (transposed)** | TF `dPHIdg − λᵀdRdg`, TY filter concept | ✅ present + fan-flow chain rule fixed |
| Filtering | Explicit radius/convolution filter (r ≈ 2–4 cells), gradient filtered with the same transposed operator | 88-line chain-rule filter; TY cone filter | ✅ present |
| Projection | Smooth tanh projection with continuation (near-0/1 at end) | CA projection practice | 🔜 add |
| Volume constraint | **OC with bisection on the Lagrange multiplier** (exact volume fraction) as the v2 upgrade; keep soft penalty as v1 | TF OC, TY OC | 🔜 upgrade |
| Update | OC with move limit 0.2 + continuation; **MMA** (re-implemented small version) only when pressure + volume constraints run together | TF/TY (OC), STO (MMA) | 🔜 upgrade path |
| Geometry extraction | Threshold ρ=0.5 → marching-squares contour → polygon cleanup → **DXF** → extrude | TF `export.m` (DXF), TY STL | 🔜 add DXF |
| Visualization | matplotlib 2D fields (design/velocity/pressure) + binary overlay | TF `postproc.m`, TY | ✅ present |
| Dependencies | numpy, scipy, matplotlib only | TY | ✅ satisfied |

**Explicitly rejected for production:** TF's symbolic codegen (MATLAB); FEniCS-based CA/DA (heavy deps,
GPL); STO's CUDA stack (complexity ≫ benefit at 2D scale, unlicensed); SOF's continuous adjoint (more
fragile than discrete adjoint on structured grids; OpenFOAM-bound).

**Validation plan (matches STO practice):** finite-difference gradient checks per stage (already in our
test suite) and cross-checks against TF's published double-pipe / pipe-bend results on identical physics.

## Verbatim key formulas worth preserving in our solver (from the references)

1. Borrvall–Petersson: `alpha(ρ) = α_min + (α_max − α_min)·q·(1−ρ)/(q+ρ)` (TF) ≡ `α_min + (α_max−α_min)·ρ·(1+q)/(ρ+q)` (STO). Our `q·ρ/(q+1−ρ)` is the same family — pick one sign convention and keep it.
2. α_max heuristic: `2.5·μ/h²` (TF `0.01²`, CA `1e2²`) — with `h` the cell size.
3. Dissipation objective: `J = ∫ (½α|u|² + ½μ|∇u|²) dx` (TF, CA) — the standard pressure-drop surrogate for Stokes flow.
4. Discrete adjoint: `Jᵀ λ = ∂J/∂u`, gradient `dJ/dρ = ∂J/∂ρ − λᵀ ∂R/∂ρ` (TF, STO, DA).
5. OC update: `ρ_new = max(0, max(ρ−mv, min(1, min(ρ+mv, ρ·max(1e-10, −sens/λ)^(1/3)))))` with bisection on λ for the volume fraction (TF, TY).
6. Continuation: step q through `[q₀, 2q₀, 10q₀, 20q₀]`, ~50 iterations per step, or on 5 consecutive small changes (TF).
7. Gradient check: central differences with `dx = 1e-2` per design cell (STO `Numerical_Derivative`).
